# 功能测试用例

按[设计](../docs/设计.md)、[企业管理设计](../docs/企业管理设计.md)和界面约定写的用例，测试代码在 `e2e/specs/`，每条测试上面一行注释写出处。最近一次完整运行（`npm run test:e2e`，2026-11-02）：共 **42** 条，全部通过，用时约 1 分 40 秒。

| 测试文件 | 条数 | 怎么跑 |
| --- | --- | --- |
| `specs/admin.test.mjs` | 25 | 测试里起一个服务端（临时数据目录），无头 Chromium 点管理端网页 |
| `specs/team.test.mjs` | 17 | 起服务端，再起一套临时 DSH，用目录联接装上鲸翼个人版和本仓库的员工端，点鲸翼里的页面 |

同一个文件里的用例按顺序跑、共用一个服务端（和一套 DSH），后面的用例接着用前面建好的数据。每条用例都核对：页面没有报错、没有发往外网的请求。

## 管理端（ADM）

| 编号 | 用例 | 预期 |
| --- | --- | --- |
| ADM-01 | 初始化向导 | 两次密码不一致、初始化码不对都在表单里说明原因；填对后进概览，侧栏显示企业名；没填对外地址时概览提醒 |
| ADM-02 | 登录和退出 | 密码错提示“登录名或密码不对”；成员账号登录提示不能进管理端；退出后回到登录页，刷新还是登录页 |
| ADM-03 | 部门 | 新建用右侧抽屉、结果右上角提示；“新建下级部门”默认选好上级；改名或移动时上级部门里没有自己和下级；删除用红色居中确认 |
| ADM-04 | 成员 | 新建账号、调部门、重置密码后旧登录失效；停用（确认框写明个人内容和负责的事项不受影响）后令牌马上失效、显示“已停用”；能重新启用；按名字找；自己没有“停用账号” |
| ADM-05 | 邀请 | 默认邀请到左边选中的部门；链接只显示一次、能复制；浏览器打开链接看到加入说明；邀请记录显示用量和状态；撤销后链接打开显示用不了 |
| ADM-06 | 团队知识 | 加号卡片新建空间（标识自动去掉大写和符号）；新建、修改笔记；别人先改过时保存被拒，提示里有“读取最新内容”，读回后能改；上传 .md；删除笔记 |
| ADM-07 | 可见范围和维护人 | 选“指定部门和成员”后加部门可见、加成员当维护人，卡片上写“研发中心可见 · 维护人：张三” |
| ADM-08 | 团队专家 | 新建后预览显示名称、“团队”和介绍；表单改介绍、技能、提示词后预览跟着变；模板原文写坏保存被拒 |
| ADM-09 | 团队技能 | 新建自带 SKILL.md 且不能删；上传压缩包（外面多一层目录也认）先确认再整体替换；SKILL.md 的 name 写错被拒 |
| ADM-10 | 删除和放弃修改 | 抽屉有改动时按 Esc、点“取消”都先问“放弃修改”，“继续编辑”改动还在；删除内容项用红色居中确认 |
| ADM-11 | 设置 | 改企业名称后侧栏跟着变；对外地址写错被拒、写对后邀请链接用它；原密码错被拒；改密码成功 |
| ADM-12 | 操作记录 | 有前面做过的管理操作；按“部门”“团队内容文件”筛选；不含密码 |
| ADM-13 | 窗口宽度（375、768、1280、1920 各一条） | 每个页面都没有横向滚动；概览卡片每行 2、3、3、6 张；1920 宽时内容区铺开 |
| ADM-14 | 深色模式 | 背景深、文字浅，卡片比背景亮一点 |
| ADM-15 | 响应头和缓存 | 网页带内容安全策略、不许被嵌入；首页不缓存，带指纹的脚本长期缓存；直接打开子页面能进 |
| ADM-16 | 管理员平级 | 新建账号选“管理员”就不挂角色；能重置另一位管理员的密码、停用再启用他；编辑自己时身份改不了，写明请另一位管理员来改 |
| ADM-17 | 角色与权限、部门负责人 | 预置“负责人”写明管理范围和权限点；加号卡片建“小组长”（管理范围，勾派事项、调整事项、看团队看板）；有人用着的“成员”删不掉，提示原因；给张三换成“小组长”后标“还不是负责人”，在部门“…”里设成研发中心负责人后提示消失、名字旁标“负责人” |
| ADM-18 | 事项类型 | 预置“任务”的五个状态；加号卡片建“开发”：改状态名、加单选字段；前缀小写自动大写，和“任务”重复被拦下；停用后标“已停用”，能重新启用 |
| ADM-19 | 全局看板和调整事项 | 研发中心一行写负责人和进行中、逾期；点部门、点下级部门、点人，看他的事项（写“逾期 3 天”）；管理员改截止日期和优先级并写一句动态，动态里写清从什么改成什么，操作记录里有，写明是本人操作 |
| ADM-20 | 项目和回收站 | 新建项目选成员；改成“已结束”；事项放进回收站（确认框写明彻底删除只能在服务器上用命令行），回到这个人的列表里已经没有它；回收站里写清谁删的，恢复后回收站空了 |

## 写这些测试时发现并修掉的问题

- 管理端编辑抽屉底部的“取消”直接关闭，不问“放弃修改”（Esc、× 会问）。现在“取消”由抽屉组件统一放，走同一条确认。
- 管理端“谁能看”“维护人”外面套的是 `<label>`，点说明文字会把可见范围误切回“全员”。现在用分组容器。
- 员工端登记给鲸翼的技能目录如果写成短文件名（如 `USERNA~1`）或经过联接，鲸翼和 DSH 报上来的真实路径对不上，团队技能不显示。现在登记前先换成真实路径。
- （第二版）管理端抽屉保存失败时，错误已经在右上角提示了，但没处理的失败还会冒成页面错误。现在抽屉提交失败只提示、抽屉留着改。
- （第二版）“我的工作”里事项“…”菜单的“交给专家”用的是列表里的事项，不带引用资料，小鲸拿不到笔记。现在先读一遍事项详情再交。
- （第二版）账号被停用后，同步和“我的工作”、名单这几个请求同时发现登录失效，各自去删本机缓存，Windows 上同时删同一个目录报 EPERM，页签卡住（TEAM-12 偶尔失败）。现在登录失效只撤一次，单元测试里也补了这一条。

## 还没覆盖的

- DSH 桌面版（Electron）里没跑，这里用的是 DSH 的网页界面。
- 员工端的深色模式、窄窗口和装了皮肤的样子。
- 用团队专家真的开会话、让模型调用团队技能，以及让小鲸、专家真的调 `team_work` 并在 DSH 的审批框里点同意（都要真实模型，功能测试不调模型；`team_work` 的审批流程在单元测试里用假的应答测了）。
- 离线超过企业规定天数后团队内容收起来（时间在单元测试里用假时钟测了）。
