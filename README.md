# 鲸翼企业版

**鲸翼企业版**以开源的[鲸翼个人版](https://github.com/gwen-liu/whalewing)为底座，把每个人的 DSH 超级个体工作台连成团队：企业集中维护**团队知识、团队专家、团队技能**，按部门和人分配谁能看、谁能改；团队每天的工作（**事项、项目、我的工作、团队看板**）也放进 DSH，小鲸助手和专家团用员工自己的权限查和改；企业还可以把小鲸助手改成自己的叫法。员工在自己的鲸翼里直接用，个人版原来的功能一样不少。

> 最新发布版 `0.2.1-rc.5.1`（[预发布](https://github.com/gwen-liu/whalewing-enterprise/releases/tag/v0.2.1-rc.5.1)），适配 DeepSeek Harness（DSH）`0.2.1-rc.5`；当前开发版本 `0.2.1-rc.5.2`。

## 由三部分组成

| 部分 | 装在哪 | 包名 |
| --- | --- | --- |
| 服务端 | 企业自己的服务器（每家企业一份，数据都在自己手里） | `whalewing-enterprise-server` |
| 管理端网页 | 随服务端一起，浏览器打开 `/admin/` | （带在服务端里） |
| 员工端组合包 | 员工电脑上的 DSH，和鲸翼个人版一起装 | `dsh-whalewing-enterprise` |

- **模型不经过服务端**：模型仍在员工各自的 DSH 里调用，服务端只存和发团队内容，不保管模型 Key，不需要显卡。
- **服务端拿不到个人内容**：员工的个人知识、个人技能和会话从不上传；只有员工点“提交到团队”的那一篇才发给企业。
- **权限在服务端判断**：员工端只拿得到自己能看的内容。

## 管理员：装服务端

要 Node.js 24 或更新：

```bash
npx whalewing-enterprise-server@0.2.1-rc.5.1 --data ./data
```

或者用 Docker：

```bash
docker compose up -d
```

第一次启动会打印初始化码，打开 `http://服务器地址:8730/admin/`，按向导填企业名称、建第一个管理员。员工从外网连接时必须配 HTTPS。详见[部署说明](docs/部署.md)。

## 员工：装员工端

1. 在 DSH「插件 → 添加插件」先装鲸翼个人版 `dsh-whalewing@0.2.1-rc.5.2`（或更新的 rc.5 版本；下一版起要 `0.2.1-rc.5.4` 或更新）。
2. 再装 `dsh-whalewing-enterprise@0.2.1-rc.5.1`，点“立即启用”。
3. 打开鲸翼的「团队」页签，粘贴管理员发的邀请链接。确认是要加入的企业后，设置自己的登录名和密码。

连上后：「团队」页签里有我的工作、团队看板（负责人才有）、项目和团队资料；团队专家出现在“专家团队”里（标“团队”），团队知识和个人知识一起搜索，团队技能出现在技能库的“扩展 · 团队”一组；小鲸和专家能用 `team_work` 工具查和改事项，改之前先请员工点同意；管理员在设置里起了助手名称时，鲸翼里的小鲸助手换成这个名字。退出团队后这些都从本机撤掉、助手恢复叫“小鲸助手”，个人内容不动。

## 版本号

版本号 = 适配的 DSH 完整版本号 + 企业版自己的序号。`0.2.1-rc.5.1` 就是适配 DSH `0.2.1-rc.5` 的第 1 版。服务端、管理端、员工端用同一个版本号；服务端和员工端能不能配合看接口版本（现在是 2：企业管理第二版改了角色，服务端和员工端要一起升级），接口版本相同时旧服务端也能配新员工端。
