# 开发

## 仓库结构

npm 工作区，四个部分：

| 目录 | 是什么 | 入口 |
| --- | --- | --- |
| `shared/` | 接口版本、错误码、地址和路径校验、专家模板解析、zod 接口定义 | `src/index.js` |
| `server/` | 服务端（Fastify + `node:sqlite`） | `bin/whalewing-enterprise-server.js`、`src/app.js` |
| `admin/` | 管理端网页（React + Vite），构建到 `server/admin-dist` | `src/main.jsx` |
| `plugin/` | 员工端 DSH 组合包；`src/` 是源码，`index.js`、`client.js`、`cordis.patch.yml` 是构建产物 | `src/host.js`、`src/client.jsx`、`src/engine.js` |

员工端声明的 `@deepseek-ai/*` 和 `zod` 是运行时由 DSH 提供的，`.npmrc` 里关掉了自动安装这类依赖；构建时它们留作外部引用，不打进包里。

## 构建和测试

```bash
npm ci
npm run build   # 管理端网页 + 员工端组合包
npm test        # 共用部分、服务端、员工端的完整回归
```

- 服务端测试用 Fastify 的内存请求打接口，每个测试一个临时数据目录。
- 员工端测试把核心逻辑（`plugin/src/engine.js`）对着一个真正监听端口的服务端跑：加入、同步、权限变化、维护、停用、离线、退出；企业管理的事项查询、“我的工作”离线缓存和模型工具 `team_work`（`plugin/src/tool.js`，审批用假的应答）也在这里测。助手名称用照个人版规则写的假接口（同一时间只认一个扩展、改名用 `set`、撤销后恢复）测起名、改名、清空、退出、登录失效、离线太久和冲突。
- 本机跑服务端：`npm start`（数据在 `.artifacts/dev-data`）。管理端网页在服务端启动时读进内存，改了网页要重新构建再重启服务端；也可以 `cd admin && npx vite`，它会把接口转给 8730 端口。

## 功能测试

在真实浏览器里按业务流程点界面，用例清单见 [e2e/cases.md](../e2e/cases.md)：

```bash
npm run build
npm run test:e2e
```

- `e2e/specs/admin.test.mjs`：测试里起一个服务端，无头 Chromium 点管理端网页。
- `e2e/specs/team.test.mjs`：起服务端，再起一套临时 DSH（独立的 `DSH_HOME` 和 profile），用目录联接装上鲸翼个人版和本仓库的员工端，点鲸翼里的「团队」页签、专家团队、个人知识和技能库。测完关掉 DSH、删掉临时目录（遇到联接只删链接本身）。
- 需要 Playwright 的 Chromium：`npx playwright install chromium`（本机已有同版本的浏览器缓存就不用再装）。
- 员工端那组还要鲸翼个人版和 DSH：`WWE_E2E_WHALEWING` 指向个人版插件目录（要适配同一个 DSH 版本、带专家来源、知识来源和助手名称接口的版本，现在是 `0.2.2-rc.1.1` 起，已发 npm；用个人版开发目录时要装好它的开发依赖），不设时依次找仓库同级的 `whalewing/`、`WhaleWing/plugins/whalewing/`；`WWE_E2E_DSH_BIN` 指向 DSH 的 `lib/bin.js`（版本要和员工端的 `engines.dsh` 一致，现在是 `0.2.2-rc.1`，不一致时 DSH 不加载员工端），不设时从个人版的开发依赖里找。找不到时直接报错，不跳过。
- `WWE_E2E_OUT` 指定失败截图放哪（默认系统临时目录下的 `wwe-e2e-evidence`）；`WWE_E2E_KEEP` 设了以后，DSH 启动失败时保留临时目录。
- 测试里只连 127.0.0.1，发往外网的请求一律拦下并算失败；去掉本机的 Key、Token 类环境变量。

## 在 DSH 里验证员工端

测试通过不等于员工真的能用，员工端改动要装进一个独立的 DSH profile 实际看：

1. 用独立的 `DSH_HOME` 和 profile，不碰正式的 desktop profile。先备份 profile 的 `package.json`、`pnpm-lock.yaml`、`pnpm-workspace.yaml`、`cordis.yml` 和 `DSH_HOME` 下的 `.credentials.yaml`。
2. 用 DSH 原生命令装鲸翼个人版和员工端发布包：`dsh plugin --profile <名字> add dsh-whalewing@<版本>`（要适配同一个 DSH 的版本，现在是 `0.2.2-rc.1.1` 或更新）、`dsh plugin --profile <名字> add <员工端 tgz 的绝对路径>`。DSH 要用和员工端 `engines.dsh` 相同版本的原版。
3. 起本机服务端、建演示内容，在 DSH 网页界面里走：加入（确认弹窗）→ 团队页签 → 专家团队里的团队专家（维护人编辑保存）→ 知识搜索和阅读团队笔记 → 技能库“扩展 · 团队” → 管理端设置里起助手名称、刷新后鲸翼里的小鲸换名 → 退出团队后三处团队内容都撤掉、助手恢复“小鲸助手”。
4. 卸载两个插件，profile 配置和凭据文件按备份逐字节核对，删掉 profile 下测试留下的 `whalewing-enterprise/` 缓存目录。
5. 适配新的 DSH 版本时，再验一遍员工的升级路径：用 `dsh plugin --profile <名字> allow-version <包名@旧版本> --dsh-version <新 DSH 版本> --accept-risk` 临时放行旧版个人版和员工端、装上并加入团队，再用 `revoke-version` 撤掉放行（等于 DSH 升级前装着旧版、升级后的样子，插件页标“异常”）；然后在插件页「添加插件」先后填两个新版的安装包地址原地换新版，重启后不用重新加入、团队内容都在。放行会在 profile 里留下 `compatibility.json`，验完按备份删掉。

## 发布

只在维护者明确说“封版”时做：

1. 三个部分的 `package.json` 版本一致（`scripts/pack.mjs` 会核对）；`npm run build`、`npm test`、`npm run test:e2e` 全过；员工端发布包按上一节在 DSH 里装上验过。
2. `node scripts/pack.mjs` 在 `.artifacts/release/<版本>/` 打出两个 `.tgz`；构建镜像时同时加上 `--label org.opencontainers.image.source=https://github.com/gwen-liu/whalewing-enterprise` 和 `--annotation "index:org.opencontainers.image.source=https://github.com/gwen-liu/whalewing-enterprise"`（用 `docker buildx build ... --load`）。Docker 推上去的是带证明清单的镜像索引，GitHub 看索引上的 annotation：0.2.1-rc.5.1 只加了 label，镜像没关联到仓库；0.2.1-rc.5.2 加了 annotation 后关联上了。
3. 打标签 `v<版本>`，推送，建 GitHub Release（没到投产标预发布），附两个 `.tgz`、Docker 镜像文件（`docker save`）和 SHA-256。
4. 维护者在自己的终端 `npm login` 后，分别 `npm publish <tgz> --tag latest` 发两个包；每次发布都要在浏览器里确认，确认链接大约 5 分钟后作废（npm 报 `404 Not Found - GET .../-/v1/done`），超时了重新运行即可。npm 11 发完提示 “Your package is being processed”，要过几分钟 `npm view` 才查得到；本机 `npm view` 还可能读到缓存里的旧版本列表，确认时加 `--prefer-online`。
5. 推 Docker 镜像到 `ghcr.io/gwen-liu/whalewing-enterprise:<版本>`。`gh` 的登录要有上传镜像的权限（`write:packages`），再 `gh auth token | docker login ghcr.io -u Gwen-Liu --password-stdin`；Docker 登录要在 gh 拿到新权限之后做，否则推送报 `The token provided does not match expected scopes`。GitHub 用户名改过时 `gh auth refresh` 会报 `received credentials for <新名>` 并作废授权，要用 `gh auth login -h github.com -s write:packages,workflow,delete_repo --web` 重新登录。第一次推上去的镜像默认私有，要在 GitHub 包页面的设置里改成公开，再不登录拉一次确认。
6. 等 npm 能下载到后触发国内镜像同步：`curl -X PUT https://registry.npmmirror.com/-/package/<包名>/syncs`，再从镜像实装验证一遍：服务端用 `npx --registry https://registry.npmmirror.com whalewing-enterprise-server@<版本>`（`--registry` 写在包名后面会被当成服务端参数），员工端在隔离 profile 用 `dsh plugin add dsh-whalewing@<个人版版本> dsh-whalewing-enterprise@<版本> --registry https://registry.npmmirror.com/`。
7. 开发版本的最后一段加 1。
