# 鲸翼企业版：企业管理设计

> 状态：**定稿**，2026-11-02 维护者定下全部待定项（见末尾“已定”）；按“分几版做”开发，还没开工。
> 第一版（见[设计](设计.md)）做了团队知识、团队专家、团队技能。本篇加第三块：**企业管理**——团队每天的工作（事项）、谁管谁（组织和权限）、每个人和每个组做得怎样（看板、日报）。

## 一句话

团队的日常工作放进员工每天用的 DSH 里，小鲸助手和专家团从第一天起就能读、能改——用员工自己的权限，在员工自己的电脑上跑。

## 为什么放在鲸翼里做

- **工作本来就在 DSH 里发生。** 写代码、写文档、查资料、整理会议记录都在 DSH 里做。事项和进度就放在旁边，模型做事时顺手就能查、能更新，员工不用切到另一个系统手填。
- **在现成系统上加 AI，AI 只看得到被手填进去的那一点。** 填不填、填得准不准全靠人。这里的模型能看到员工当天实际做了什么（只在员工本机，员工确认后才上报），所以日报、进度、风险都能有依据地起草。
- **AI 和人走同一套权限。** 模型通过工具调服务端，服务端按这个人的身份判断，不给模型开后门；人做不了的事，模型也做不了。

## 叫法

- **事项**：团队里要做的一件工作。不叫“任务”，因为 DSH 已经有“定时任务”“后台任务”和给模型用的待办，混在一起分不清。
- **项目**：一组事项属于同一个项目。
- **动态**：事项的变化记录和评论。
- **填报表**：负责人建的一张表，范围里的人定期各填一行。日报、周报都是填报表。
- **我的工作**、**团队看板**：员工端「团队」页签里的两个页面。
- **小鲸助手**：鲸翼自带的助手。企业可以改成自己的叫法，见“助手改名”。

## 从常见团队管理系统里吸取的教训

下面是这类系统常见的问题，企业管理按右边一列来做：

| 常见问题 | 后果 | 这里怎么做 |
| --- | --- | --- |
| “我的看板”按**创建人**统计，旁边又写着“只显示你负责的” | 普通成员几乎不建事项，看板全是 0，说明文字和数字对不上 | “我的”一律按**负责人**算；创建人只是一条记录 |
| 实施、接口、开发、跟踪各建一张表，字段八成一样，编号、状态叫法、“完成日期”的名字各不相同 | 改一处要改四处；跨类型的统计算不了 | **一种事项 + 类型**。类型只决定编号前缀、状态叫法和少数专属字段 |
| 进度手填，和状态脱节：已完成的事项进度 45%，已关闭的 0% | 平均进度没意义 | 状态归到五个大类；已完成就是 100%，未开始就是 0；有检查项时按检查项算 |
| 权限写在页面说明里（“删除只由某几个账号处理”），其他人都能改所有事项 | 换人就要改代码；谁改了截止日期查不到 | 角色和权限点由管理员配；每次改动进动态，写清谁、何时、从什么改成什么 |
| 只有“我的”，没有“我的团队” | 组长看不到组员做得怎样，只能挨个问 | 团队看板按管理范围汇总，可以一层层点进去 |
| 每一行都显示同一个关联项目；表格十几列，要横向滚动才看得到操作 | 关键信息被挤掉 | 项目放到筛选和页头；列表只留关键几列，其余进详情抽屉 |
| 没数据时画一个空坐标轴 | 看不出是没数据还是坏了 | 没数据时说清为什么没有、下一步做什么 |
| 资料库和事项分开，文档挂不到事项上 | 找资料靠记忆 | 事项直接引用团队知识里的文档 |
| 没有日常节奏：没有“今天要做什么”，没有日报，进度改了没记录 | 管理只剩月底对表 | 我的工作（今天）+ 填报表 + 动态 |

## 角色和权限

### 两件事分开：能做什么、能看谁的

- **能做什么**（功能权限）：比如能不能派事项、能不能删除。这是 RBAC（基于角色的权限控制）管的：人 → 角色 → 权限点。
- **能看谁的数据**（数据范围）：比如组长能看自己组员的事项。这叫数据权限或数据范围。

国内的企业系统大多是这两样配合着用。这里也一样：**角色 = 一组权限点 + 一个数据范围**。

### 超级管理员在系统之外，管理员在系统之内

| | 超级管理员 | 管理员 |
| --- | --- | --- |
| 在哪 | 系统之外：代码、服务器、数据库 | 系统之内：管理端网页和员工端 |
| 是谁 | 项目维护者，只有这一个身份；不是系统里的账号 | 企业自己任命，可以有很多个 |
| 能做什么 | 改代码、登服务器、直接改数据库、看服务器日志、备份恢复、救急 | 系统里的全部业务：组织和人员、角色、事项、项目、看板、填报、团队内容、邀请、企业设置、操作记录 |

- **系统里没有“超级管理员”这个角色，也没有比管理员更高的账号。** 想要超级管理员的能力，只能改项目本身或者登上服务器，这本来就在系统之外。
- 维护者自己部署的服务器（比如测试部署），超级管理员就是维护者。企业自己部署服务端时，管那台服务器的人对那一套部署也有同样的能力，系统拦不住；部署说明里要写清楚：服务器和数据库的权限要像管理员账号一样管好。
- 原来打算放进网页的高危操作，都留在系统之外（具体命令开发时再定）：

  | 操作 | 怎么做 |
  | --- | --- |
  | 看服务器日志 | 服务器上的日志文件、Docker 日志 |
  | 备份、恢复 | 服务端命令行 |
  | 安全设置：登录锁定、令牌有效期、内网是否允许 HTTP | 服务端配置文件 `server.json` |
  | 彻底删除回收站里的东西 | 服务端命令行 |
  | 管理员全都登不上了 | 服务端命令行重置密码 |

- **管理员是系统里的最高权限**：调整任何人的事项（截止日期、优先级、负责人）、建组织、配角色，都由管理员做。管理员之间平级，都能任命、停用别的管理员，重置他们的密码；最后一个启用的管理员不能被停用或降级。这些操作都进操作记录。
- 第一版的“所有者”升级后就是一个普通的管理员。

### 管理员自己定义的角色

管理员按企业自己的叫法建角色：负责人、小组长、组员、项目经理……都行。每个角色勾一组权限点、选一个数据范围。

**权限点**（故意只有这几个，不做几百个开关）：

| 权限点 | 能做什么 |
| --- | --- |
| 新建事项 | 给自己建事项（默认人人都有） |
| 派事项 | 给范围内的人建事项、改事项的负责人 |
| 调整事项 | 改范围内事项的截止日期、优先级、状态 |
| 删除事项 | 把范围内的事项放进回收站 |
| 看团队看板 | 看范围内的汇总和每个人的事项 |
| 管填报 | 给范围内的人建日报、周报这类填报表，看他们填的内容 |
| 管项目 | 建项目、管项目成员 |
| 导出 | 把范围内的事项和填报导出成表格 |

管组织和人员、管角色、事项类型、企业设置、从回收站恢复，这些只给管理员，不能分给自定义角色（以后要“负责人管自己部门的人”再加）。

**数据范围**三选一：

| 数据范围 | 意思 |
| --- | --- |
| 仅本人 | 只管自己负责的事项 |
| 管理范围 | 他担任负责人的部门，连同下级部门 |
| 全部 | 全企业，比如管理办公室 |

预置两个角色，管理员可以改名、改权限或删掉：**负责人**（管理范围，除删除外的权限点都勾上）、**成员**（仅本人，只有新建事项）。第一版的“成员”升级后就是这里的成员。

### 上下级从哪来：组织树 + 部门负责人

不给角色排“第几级”。组织是一棵部门树（第一版已经有），每个部门可以设一个或几个**负责人**。一个人担任负责人的那些部门，连同下级部门，就是他的管理范围。

```
公司                      管理员：甲
└─ 交付中心               负责人：乙（角色“负责人”）
   ├─ 一组                负责人：丙（角色“小组长”）   成员：丁、戊
   └─ 二组                负责人：己（角色“小组长”）   成员：庚
```

- 乙的范围是交付中心、一组、二组；丙只有一组；己只有二组。**上级比下级看得多，是树自己带出来的**，不用另外配。两个小组长互相看不到对方的组。
- 负责人和小组长的区别由管理员定：比如负责人能删除事项、小组长不能。
- 一个人可以兼管几个部门（在几个部门都设成负责人）。跨部门的合作用**项目成员**解决，不用改组织树。
- 角色是“管理范围”、但他还不是任何部门的负责人时，实际上只能管自己；管理端会提示。

### “看”和“改”分开

- **改**：自己负责的事项，能更新进度、状态和动态；别人的事项，要在自己的数据范围里，并且有对应的权限点。
- **看**：默认能看到 = 数据范围里的 + 自己参与的（负责、协作、创建、在等我）+ 同项目成员的事项。企业设置里可以改成“全员可见”，适合人少、讲透明的团队。

### 防止越权

- 全部在服务端判断（沿用第一版）；小鲸和专家调工具也走同一套判断。
- 看不到的事项一律回“不存在”，不让人从报错里猜出有哪些事项。
- 删除先进回收站，管理员能恢复；彻底删除只能在服务器上用命令行。
- 改截止日期、优先级、负责人、删除，都记进事项的动态和操作记录：谁、什么时候、从什么改成什么、是本人操作还是经模型操作。

## 事项

### 一种事项，多种类型

| 字段 | 说明 |
| --- | --- |
| 编号 | 自动生成：`类型前缀-年月-序号`，如 `KF-202611-007`；删掉的号不再用 |
| 标题 | 必填 |
| 类型 | 管理员定义，见下 |
| 项目 | 可以不属于任何项目 |
| 负责人 | 只有一个；“我的工作”按它算 |
| 协作人 | 可以多个，能看、能写动态 |
| 创建人 | 自动记 |
| 状态 | 用类型自己的叫法，每个状态归到一个大类 |
| 优先级 | 高、中、低 |
| 开始日期、截止日期 | 截止日期用来算逾期 |
| 完成时间 | 状态进入“已完成”时自动记 |
| 进度 | 见下 |
| 等待 | 在等谁、等什么，一句话 |
| 内容 | Markdown |
| 检查项 | 可选的小清单 |
| 引用资料 | 团队知识里的笔记 |
| 专属字段 | 类型自己的几个字段 |

**类型**由管理员在管理端配：名称、编号前缀、状态列表（每个状态归到哪个大类）、最多 5 个专属字段（单选、文本、日期）。预置“任务”一个类型，管理员照着加“开发”“实施”“跟踪”这类。

**五个状态大类**：未开始、进行中、等待中、已完成、已取消。所有统计都按大类算，所以各类型的状态叫法可以不一样，看板照样能合起来。

### 进度和逾期

- 已完成 = 100%、未开始 = 0%，自动；只有进行中、等待中的事项才填进度。
- 有检查项时进度按检查项完成的比例算，不用手填。
- **逾期** = 截止日期已过，并且大类不是已完成、已取消。等待中的照样算逾期，看板上标出在等谁。

### 等待

任何事项都能标“在等谁、等什么”。被等的人在“我的工作”里看到“等我答复”。

### 动态

每个事项一条时间线：状态和进度的变化、截止日期调整、评论、关联的填报。经模型改的标“经小鲸”或“经专家 某某”。

### 项目

名称、负责人、成员、起止日期。项目成员能看项目里的全部事项。列表和看板按项目筛选；项目名放在页头，不在每一行重复。

## 日报、周报：负责人建填报表，每人填自己那一行

- 负责人（或管理员）建一张**填报表**：名称（如“一组日报”）、几列（如今天完成、遇到的问题、明天计划、工时）、谁来填（自己范围里的部门或人）、多久填一次（每个工作日、每周，或只填一次）、填的人互相能不能看见（默认能看见）、到点提醒（默认不提醒）。
- 看起来就是一张大家一起填的表：每天一张，一人一行。每个人只能改自己那一行；负责人看得到谁填了、谁没填。
- 填的时候小鲸可以起草：读**本机**今天的会话和今天的事项变化，按表里的列写好，员工改完提交。只有提交的内容发给服务端；会话原文从不上传（沿用第一版）。
- 能导出成 Excel。
- **为什么不直接用一份共享 Excel 或在线文档**：大家同时改会互相覆盖，谁都能改别人那一格；表里的文字模型读不准，没法按人、按天汇总，也没法提醒没填的人。填报表用起来和共享表格一样，但一人一行、权限清楚，模型能读能汇总。
- 只填一次的填报表也能用来临时收集，比如“每人填一下下周的请假安排”。

## 在 DSH 里怎么用

### 只有一个「团队」页签

不新开页签，把第一版的「团队」页签改成带二级导航，免得工作台页签太多太乱：

| 二级页 | 谁看得到 |
| --- | --- |
| 我的工作（默认打开） | 所有人 |
| 团队看板 | 有管理范围、或数据范围是“全部”的人 |
| 项目 | 所有人（只列看得到的项目） |
| 填报 | 所有人：要我填的表；管填报的人还能建表、看填写情况 |
| 团队资料 | 所有人：第一版的知识空间、团队专家、团队技能，以及我的信息、退出团队 |

### 我的工作

```
11月2日 周一                                            [填日报]  [+ 新事项]
┌ 逾期 2 ┐ ┌ 今天到期 1 ┐ ┌ 进行中 4 ┐ ┌ 等我答复 1 ┐ ┌ 本周完成 3 ┐

先处理
  KF-202611-003  登录页改版            逾期 2 天    进度 90%     [更新]
  GZ-202611-001  需求范围确认         等我答复（来自 乙）          [答复]
本周
  SS-202611-004  测试数据准备          周四到期     进度 40%     [更新]
  ……
```

- 上面的数字卡片可以点，点了只筛选下面的列表，不跳页。
- “更新”打开右侧抽屉：改状态、进度，写一句动态。也可以直接跟小鲸说“登录页那个做完了，已经上线”。
- 每个事项的“…”菜单里有“交给专家”：打开小鲸，带上这个事项，由小鲸转交给合适的专家。
- 连不上服务端时，显示上次同步的“我的工作”，标明是缓存，不能改。

### 团队看板

```
一组 · 5 人                    范围 [一组 ▾]   项目 [全部 ▾]      [让小鲸分析]
┌ 进行中 12 ┐ ┌ 逾期 3 ┐ ┌ 等待中 2 ┐ ┌ 本周完成 9 ┐ ┌ 今日日报 4/5 ┐

成员       进行中  逾期  等待中  本周完成  今日日报
  丁         3      1      0        2        已填
  戊         4      2      1        1        未填
  ……
```

- 负责人先看到的是各下级部门的汇总，点一个部门进去是同样的表，再点一个人看他的事项。
- 管理员默认看全企业。
- 组长自己的事项在“我的工作”里，不混在看板里。
- 有权限时可以在这里给组员派事项、改截止日期和优先级（右侧抽屉）。
- “让小鲸分析”：带着当前范围和筛选打开小鲸，比如分析谁有风险、哪些事项卡住了、和上周比怎样。

## 原生 AI：小鲸助手和专家团

### 小鲸是企业管理的 AI 入口

- 企业版里，小鲸助手就是企业管理的入口。领导问“这周一组怎么样，帮我分析一下”，小鲸查他范围里的看板数据，做分析、出图表；要深入时交给数据专家（个人版已有的“小鲸转交任务”）。
- **专家团也能干企业的活**：研发专家做完一个事项，顺手更新进度、写动态；企业可以用第一版的团队专家，做“项目经理”“周报整理”这类专家发给全员。
- 界面上的入口：看板上的“让小鲸分析”、事项菜单里的“交给专家”，都用工作台公开的 `assistant.open` 带着问题打开小鲸，由小鲸处理或转交专家。
- **做得到**：个人版现在只在专家会话里隐藏没绑定的 MCP 工具，插件自己登记的工具（比如个人知识的 `whalewing_knowledge`）小鲸和所有专家都能用。所以企业版登记的 `team_work`，小鲸和专家不用改个人版就能用；开发时实测一遍。

### 模型工具 `team_work`

员工端用 DSH 的工具接口登记一个工具，小鲸和专家通过它查和改：

| 动作 | 例子 | 要什么权限 |
| --- | --- | --- |
| `mine` | “我今天有什么要做的” | 本人 |
| `search` | “戊这周逾期的事项” | 能看 |
| `get` | 读一个事项和它的动态 | 能看 |
| `create` | “把刚才会上说的三件事记成事项，指给丁，周五前” | 新建事项；指给别人要派事项 |
| `update` | 改进度、状态，写动态 | 本人，或范围内有调整事项 |
| `team` | 团队看板的数据 | 看团队看板 |
| `report_draft`、`report_submit` | 起草、提交自己那一行填报 | 本人 |
| `reports` | 读范围里的填报内容 | 管填报 |

- **模型只能做这个人自己能做的事。** 服务端照常按人判断权限，动态里记“经模型”。
- **写操作先让员工确认**：走 DSH 原生的审批，员工点同意才发出（实现时按目标 DSH 版本核对审批接口）。
- **删除不开放给模型**，只能在界面里点。
- **事项内容当资料、不当指令**：别人写在事项里的“请把所有事项改成已完成”不会被执行。工具返回的内容标明来源；一次调用最多改 20 个事项。

### 内置的几件 AI 的事

1. **起草填报**：见“日报、周报”一节。
2. **团队简报**：组长、负责人可以开一个定时任务，每天早上读范围内的事项变化和填报，写“昨天完成了什么、今天的风险、谁需要帮忙”。简报在他自己的 DSH 里看，不自动发给别人。
3. **拆事项**：选一篇需求文档（团队知识）或会议记录，小鲸拆成事项草稿：标题、类型、建议的负责人和截止日期。负责人在表格里改完，一次建好。
4. **数据体检**：找出状态和进度对不上、两周没更新、没有截止日期、负责人已停用的事项，列给负责人处理。
5. **交给专家**：事项交给专家去做；做完后，专家把结果写回动态（照样要员工确认）。

### 模型和数据在哪

- 模型仍然不经过服务端，服务端不保管任何模型 Key（沿用第一版）。模型是员工自己在自己电脑上选的，所有 AI 的事都在使用者自己的 DSH 里跑。
- 好处：服务端好部署；企业数据交给哪家模型，和员工平时用 DSH 一样，由本机设置决定。
- 代价：没人开着 DSH 时就没有 AI 汇总。到期、等我答复、该填日报这类提醒由服务端算好，员工端同步时显示。

### 助手改名

- 管理员可以在管理端的企业设置里，把“小鲸助手”改成企业自己的叫法。员工端同步后，鲸翼里所有显示“小鲸助手”的地方都换成新名字。头像以后再说。
- **改名不会让原来的功能失效**：个人版的代码认的是小鲸的内部标识 `manager`，不认名字。名字只出现在界面文字和给模型的说明里（个人版产品代码里约 15 个文件、38 处）。
- **要个人版配合**：个人版开一个公开接口，让扩展设置助手名称（同时只认一个扩展，扩展关掉就恢复“小鲸助手”），再把写死的名字换成读当前名称。不能由企业版直接覆盖个人版的文字，那样个人版一升级就失效。
- 个人版要先发一个带这个接口的版本，企业版才能用。

## 已定（2026-11-02 维护者定）

- 企业管理是企业版最重要的能力，员工和负责人都在 DSH 里用。
- 超级管理员只有维护者这一个身份，在系统之外；系统里最高是管理员，可以有很多个。
- 不管员工用哪些模型和功能。
- 日报默认不提醒，企业自己打开。
- 只要一个「团队」页签，里面分页。
- 事项默认能看到：数据范围里的 + 自己参与的 + 同项目的；企业设置里可以改成全员可见。
- 日报、周报做成负责人建的填报表，一人一行，不用共享在线表格。
- 助手改名放第三版。
